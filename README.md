# fast_parser

Локальный сборщик новостей российских государственных СМИ. Это отдельный сервис на ноутбуке: он не обязан работать круглосуточно. При каждом запуске читает то, что сейчас отдают RSS-ленты, сверяет с уже сохранённым и дописывает только новое. Лента хранит последние N записей и историю не отдаёт, поэтому «догнать пропущенное» здесь значит забрать всё доступное окно и отбросить дубли.

Сейчас это версия 0.3.1: сбор RSS, региональный каталог, веб-интерфейс, рубрики и тональность. Оценка недостоверности в схеме уже есть, но пока пустая.

## Что умеет сейчас

- Два каталога. `config/sources.yaml` — 32 федеральных источника: агентства, телеканалы, газеты и органы власти. `config/sources_regional.yaml` — 129 официальных источников по всем 89 субъектам (код субъекта по перечню ФНС, название и федеральный округ). У федеральных записей регион пустой. У каждого источника сохранён статус проверки и, где есть, официальный Telegram.
- В сбор попадают только живые ленты. Пустые, закрытые антиботом и неподтверждённые остаются в каталоге, но не запрашиваются. Ленты, которые с проверочного сервера не открылись, но были подтверждены отдельно (`blocked_from_box_verified`, Кремль, правительство, «Красная звезда»), включены: сервис рассчитан на запуск с российского IP.
- Асинхронная загрузка с повторами, паузой между попытками, таймаутом на ленту и условными запросами (`ETag` / `Last-Modified`). Ошибка одной ленты пишется в журнал, остальные продолжают работу.
- Если в ленте только короткий анонс, страница новости догружается, а текст забирается через [trafilatura](https://github.com/adbar/trafilatura).
- Даты приводятся к UTC. Если часового пояса в ленте нет, время считается московским.
- Дедупликация по каноническому URL (без `utm_*`, якоря и лишнего слэша) и по хешу длинного текста внутри одного источника. Одинаковый текст у разных источников сохраняется отдельно: это нужно будущему сравнению публикаций.
- SQLite через SQLAlchemy. Для перехода на PostgreSQL достаточно другого URL базы.
- Команды: один прогон, цикл с интервалом, сводка, выгрузка JSONL и локальный веб-интерфейс `fast-parser web`.

## Что будет дальше

Дальнейшие этапы, версии и статусы — в [ROADMAP.md](ROADMAP.md). Журнал — в [CHANGELOG.md](CHANGELOG.md). Сейчас версия 0.3.1. Дальше — Telegram, 0.4.0.

Повторить цифры качества на ручной выборке из `eval/labels.jsonl`:

```bash
fast-parser eval
```

Рубрики считаются по словам и полю RSS сразу. Тональность и эмбеддинги рубрик требуют extra:

```bash
python -m pip install -e ".[ml]"
fast-parser process
```

Модели: `seara/rubert-tiny2-russian-sentiment` и `cointegrated/rubert-tiny2`, они качаются при первом запуске и дальше берутся из кэша Hugging Face. Список рубрик — `config/categories.yaml`. Если уверенность ниже `pipeline.min_confidence`, можно спросить локальную модель: `pipeline.llm.enabled: true` и endpoint вроде `http://127.0.0.1:11434/v1` (Ollama, `qwen3:8b`). По умолчанию этот запасной путь выключен. Без extra `ml` команда `process` всё равно проставляет уверенные рубрики и не падает.

## Требования

- Python 3.11 или новее.
- Ноутбук с российским IP. Часть сайтов (kremlin.ru, government.ru, redstar.ru и другие) обрывает зарубежные адреса по TLS или отвечает ошибкой. Сборщик такую ошибку логирует и идёт дальше, но сами эти ленты с иностранного IP не наполнятся.
- Запускать из корня репозитория, чтобы нашлись `config/settings.yaml`, `config/sources.yaml` и `config/sources_regional.yaml`.

## Установка

### Windows (PowerShell)

```powershell
cd fast_parser
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
python -m pip install -e ".[dev]"
```

Если `py` не находится, поставьте Python 3.11+ с python.org и отметьте «Add python.exe to PATH».

### WSL2 (предпочтительнее для SQLite)

Клонируйте репозиторий внутрь файловой системы Linux (`~/src/fast_parser`), а не в `/mnt/c`: так база не упирается в медленный диск Windows.

```bash
cd ~/src/fast_parser
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -U pip
python -m pip install -e ".[dev]"
```

Проверка без сети:

```bash
python -m pytest
```

## Настройка

Основной файл: `config/settings.yaml`. Каталоги — снимки проверки от 22 ноября 2026, их лучше не переписывать руками. Отключать ленты и целые источники можно в настройках.

- `sources_file` — федеральный каталог.
- `regional_sources_file` — региональный каталог. Чтобы собирать только федеральные ленты, уберите эту строку или задайте пустое значение.

Переменные окружения перекрывают файл:

| Переменная | Что меняет |
| --- | --- |
| `FAST_PARSER_CONFIG` | путь к `settings.yaml` |
| `FAST_PARSER_SOURCES` | путь к федеральному каталогу |
| `FAST_PARSER_REGIONAL_SOURCES` | путь к региональному каталогу |
| `DATABASE_URL` | строка SQLAlchemy, например `sqlite:///D:/data/fast_parser.db` |
| `LOG_LEVEL` | `DEBUG`, `INFO`, `WARNING` |
| `FAST_PARSER_INTERVAL` | секунды между прогонами в режиме `loop` |
| `FAST_PARSER_FETCH_FULLTEXT` | `1` / `0`, догружать ли текст страницы |

По умолчанию база создаётся в `data/fast_parser.db` рядом с текущим каталогом. Каталог `data/` создаётся сам.

Чтобы позже перейти на PostgreSQL:

```bash
pip install psycopg
# DATABASE_URL=postgresql+psycopg://user:pass@localhost:5432/fast_parser
```

Схема та же: `sources`, `feeds`, `feed_states`, `fetch_logs`, `articles`. У источника есть `region`, `region_code` и `federal_district` (у федеральных СМИ они пустые). Если база уже была создана ранней версией, при следующем запуске эти колонки добавятся сами. Статьи фильтруются по региону через источник, отдельная копия региона в статью не пишется.

Какие ленты не качаются:

- `check: empty` — валидный RSS без записей (Sputnik, сайт правительства Крыма);
- `check: antibot` — вместо XML приходит HTML-челлендж (МИД);
- `check: unverified` — лента в этот прогон не подтверждена (Минобороны);
- URL из `collector.skip_feed_urls`. Сейчас там курсы валют ЦБ: лента живая, но это не новости.

Источники только с Telegram (Первый канал, Вести, НТВ, Дума, а также большинство региональных каналов губернаторов и ГТРК) в базе есть, их каналы лежат в `telegram_username`. RSS у них в этом этапе нет. Региональные ленты со статусом `ok` собираются вместе с федеральными: сейчас это 26 региональных лент плюс 25 федеральных.

## Запуск

Один прогон, он же догон с прошлого раза:

```bash
fast-parser run
```

То же самое модулем:

```bash
python -m fast_parser run
```

Пока окно открыто, повторять каждые 15 минут (или `--interval 600`):

```bash
fast-parser loop --interval 900
```

Локальный сайт, та же база. По умолчанию только на этой машине, порт 8080:

```bash
fast-parser web
```

Страницы: лента, карточка статьи, источники, покрытие 89 субъектов, сводка. Кнопка «Собрать сейчас» делает один догон. JSON API и схема запросов: http://127.0.0.1:8080/docs

Сводка в терминале: источники, ленты в сборе, статьи, последние ошибки, разбивка по федеральным округам и по всем субъектам:

```bash
fast-parser stats
```

Выгрузка уже собранного текста:

```bash
fast-parser export --out data/articles.jsonl
```

Пример конца прогона:

```text
Прогон завершён
  ленты: 25, успешно: 22, без изменений: 1, пустые: 0, ошибки: 2
  записи: получено 480, новых 17, дублей 463, обновлено 0
```

Код возврата `0` значит, что прогон дошёл до конца. Отдельные ленты при этом могут быть в ошибках: таймаут, обрыв TLS или HTTP 500 не останавливают остальные. Код `2` — не найден конфиг или каталог.

Повторный запуск в тот же день обычно почти ничего не пишет: лента отвечает `304 Not Modified` либо все записи уже есть в базе. Состояние на ленту хранится в `feed_states` (`etag`, `last_modified`, время последнего успеха, самая новая увиденная публикация, счётчик ошибок подряд). Журнал каждого запроса — в `fetch_logs`.

Порог догрузки страницы — `collector.fulltext_min_chars` (по умолчанию 500). Текст длиннее берётся прямо из RSS, более короткий считается анонсом. Исходный URL статьи сохраняется как есть, для сравнения используется канонический.

## Пайплайн обработки

Интерфейс в `src/fast_parser/pipeline/`. Процессор получает `ArticleView` (источник, URL, заголовок, текст, авторы, дата) и возвращает `ProcessorResult`. Сейчас зарегистрированы заглушки `category`, `sentiment`, `fake_score`: они ничего не заполняют, статья остаётся в статусе `pending`.

На этапе 2 заглушка заменяется реализацией в `PROCESSOR_REGISTRY`, а в конфиге ставится `pipeline.enabled: true`. Если текст статьи потом изменился, категория, тональность и `fake_score` сбрасываются, статус снова `pending`.

Допустимая тональность: `positive`, `neutral`, `negative`.

## Тесты

Сеть в тестах не используется. Ленты лежат в `tests/fixtures/` и в фиктивном HTTP-транспорте.

```bash
python -m pytest
```

GitHub Actions гоняет то же самое на Python 3.11 и 3.12.

## Как менять проект

Номер версии один: `fast_parser.__version__` в `src/fast_parser/__init__.py`. Из него собирается пакет и ответ `fast-parser --version`. Версии ставятся по [SemVer](https://semver.org/lang/ru/).

Каждый пул-реквест:

1. Дописывает [CHANGELOG.md](CHANGELOG.md) в раздел `[Unreleased]` подзаголовками **Добавлено**, **Изменено** или **Исправлено**. Когда версия выпускается, эти записи переносятся в раздел `[X.Y.Z] - дата`.
2. Обновляет статус и целевую версию в [ROADMAP.md](ROADMAP.md), если этап сдвинулся.
3. Релиз сливается в `main` только после своей проверки и зелёных GitHub Actions. На коммит слияния ставится тег версии из CHANGELOG, например `v0.1.0`.

GitHub Actions не пропустит пул-реквест, в котором не изменён `CHANGELOG.md`. Если правка журнала действительно не нужна, на пул-реквест вешается метка `skip-changelog`.

Слияние — squash в `main`, и только когда проверки уже зелёные. Падающие или ещё не закончившиеся проверки означают, что сливать нельзя. Сначала сливается и помечается тегом более ранняя версия, потом следующая переносится на обновлённый `main`. После squash-слияния: `git checkout main && git pull && git tag vX.Y.Z && git push origin vX.Y.Z`.

Перед тем как открыть пул-реквест или обновить его описание, изменение нужно прогнать самому, а не только по зелёным тестам в голове:

1. Полный `python -m pytest`.
2. Настоящий `fast-parser run`: догон на фикстурах или на живых лентах, которые с этой машины открываются.
3. `fast-parser stats` по той же базе.
4. Если затронут веб-интерфейс — поднять `fast-parser web` и открыть страницы и JSON API. В описание пул-реквеста кладутся снимки экрана.

В описание добавляется короткий раздел **Проверено** со списком того, что реально запускалось.

## Ограничения

- Это не архив. Если между запусками лента успела вытеснить старые записи, их уже не вернуть.
- Полный текст зависит от вёрстки страницы. Если trafilatura ничего не достала, в базе остаётся анонс из RSS, а происхождение текста видно в `content_origin` (`rss` или `extracted`).
- Короткие анонсы не склеиваются по тексту: у них в хеш входит URL, иначе разные заметки с похожим заголовком схлопнулись бы в одну. Длинный одинаковый текст внутри одного источника считается дублем.
- Telegram, классификация, тональность, fake score и отправка в RAG в этот этап не входят.
